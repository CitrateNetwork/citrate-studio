# citrate-studio QA sweep — 2026-08-01

Fifth app in the Commissary cadence. T1, partner-eval.

**Two defects, both in the space between what the build produces and what the
operator is told.** Studio's own `COMPLETION_STATUS.md` is unusually rigorous — it
distinguishes ✅ real from 🟡 modeled from ⏳ remaining, per capability. Both findings
are places where that rigour stopped at the document and did not reach the binary.

`47 → 48` tests, clippy clean.

---

## 1. The defects

### S-1 — "Never ship `dev-filebacked`" was a comment, not a control

`dev-filebacked` seeds a signer roster and writes its **private keys to disk in
plaintext** (`to_json_with_secrets` in `load_or_seed`). `Cargo.toml` has said "NEVER
enable in a shipping build (audit F-3)" since that audit.

Nothing enforced it. Verified: `cargo check --release --features dev-filebacked`
**succeeded**, producing an optimized T1 binary that persists private signing
material on first run.

**Nothing shipped has ever carried it** — the release workflow is `cargo build
--release --locked` with no features, and the visual harness only ever adds
`core-live`. This does not fix a leak; it removes the possibility of one being
introduced by a build command. Same failure mode as the citrate-comms relay finding,
and the audit had already anticipated it in prose.

Now a `compile_error!` gated on `not(debug_assertions)`, so the demo and screenshot
workflow is untouched. Verified all three paths: release+flag fails with the reason,
debug+flag still builds, release-without-features still builds.

### S-2 — The Health Report reported results it never measured

`core-live` is **off by default**, so `data::doctor()` is what the shipping binary
renders. It was eleven hardcoded rows, every one `Pass`, each carrying a specific
nothing had measured:

| check | claimed |
|---|---|
| `audit-chain-integrity` | `verify_integrity ok · 11,402 records` |
| `approval-queue-depth` | `3 / 100` |
| `capsule-manifest-reverify` | `9 capsules re-verified` |
| `tla-spec-ci-status` | `35,435 states · green` |

The summary computed **`DOCTOR · HEALTHY`** off them, and nothing on the surface told
the operator the report was modeled.

This is a partner-eval product, and a Health Report is precisely what an evaluator
reads to judge operational readiness. **A doctor that always says healthy is the
diagnostic version of a verify button that cannot fail.**

The check *names* stay — an evaluator should see what this product checks, and that
list is true. The *results* are gone. Each row now reads "not measured — this build
has no runtime core (core-live off)" at `Warn`, because the operator is being told a
check did not run, which is a thing to attend to rather than a thing that succeeded.

Those thousands-separated counts are the exact form citrate-quorum's "no fabricated
stats in surfaces" ratchet exists to catch. **Studio has no such ratchet**; the new
test is a narrow version of one.

## 2. What came out clean

- **OIDC issuer validation.** `COMPLETION_STATUS` claims release builds require an
  `https://` issuer and that a plaintext loopback issuer is debug-only and loudly
  logged. Verified true: `validate_issuer` requires https, permits loopback http only
  under `debug_assertions` with a warning, and rejects non-loopback http **even in
  debug**. Tested.
- **`clips()` — the scripted demo scenario.** Fabricated specifics ("Pulled 3,402 CUI
  procurement records"), but **disclosed**: the README states the core is "modeled
  here with in-memory data + a playback loop" and names the "scripted 'run the
  reconciliation' flow". That disclosure is exactly what makes it legitimate demo
  content rather than a fabrication, and it is why S-2 needed fixing and this does
  not — the Health Report claimed to diagnose the operator's *actual system*.
- **`tripwires()`** — the literals there are threshold *definitions*
  (`RocksDB hot tier > 80%`), not measurements.
- **The `docs/partner-eval` branch** flagged by the federation census as having no
  upstream: fully merged into `main`, nothing at risk.

## 3. Open for the owner

- **The modeled/live distinction is disclosed in the README, not in the app.** An
  operator running the binary sees no in-app indication that the core is modeled. For
  a partner-eval product handed to an evaluator who may never open the README, an
  in-app build-mode badge would close the gap. That is a product decision, not a bug
  fix, so it is named rather than made.
- **Studio has no equivalent of quorum's `check.sh` ratchets.** S-2 is exactly what
  "no fabricated stats in surfaces" catches automatically over there. Porting that
  scanner would be cheap and would have found this without a human looking.
- **`AUDIT_TIER` status is PROVISIONAL-A**, downgraded for honesty in #12. The T1
  external audit remains the gate for `v1.0.0`.
