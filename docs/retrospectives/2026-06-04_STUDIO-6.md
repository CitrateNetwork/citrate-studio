## What Went Well

**1. The STUDIO-4 → STUDIO-6 bridge landed with zero adaptation.** STUDIO-4 chose
`signer_id = SHA-256(pubkey)` *specifically* to match the runtime. The payoff arrived
here: a studio `EnrolledSigner.secret` → `Ed25519FileSurface::from_seed(secret, role)`
produces an `AttestedSignature` the real `verify_attestation` + `StaticSignerRoster`
(RM-G.1) + SoD + `Quorum::satisfied_by` accept — no translation layer, because both
sides compute identity the same way. The end-to-end test (two enrolled keys satisfy a
real High gate through the real async queue) passed on the first try once it compiled.

**2. The capsules were already real.** Larry's "can you set up the cps?" question sent me
to look instead of assume — and the runtime ships 10 prebuilt WASM capsules. So
`CapsuleDispatch::load_from_dir` over `citrate-agent-runtime/capsules/` + `call_raw` on
the `hello` capsule returns a real `"Hello, Aleia"` through wasmtime. What I'd scoped as
a stub became real execution.

**3. The chain is live and it's 40204.** `rpc.citrate.ai` answers `eth_chainId` →
`0x9d0c` (40204) and a real, advancing block height. Chain reads run in the *default*
build (plain JSON-RPC over ureq) — the Settings "Chain (live)" row shows a real block
number, and offline is surfaced as "unreachable," not faked.

**4. The Doctor runs against a real chain.** `core_bridge::doctor` writes a real
`AuditChain` to a temp file and runs the runtime's own checks: integrity verifies the
chain ("verified 3 records"), permissions inspects the file ("owner-only 0600"). Real
`Severity`, computed by the real checks.

## What Didn't Go Well

**1. The async-into-sync bridge has a poll-for-registration seam.** `submit_for_action`
inserts the pending entry on the future's first poll, so `LiveQueue::open` spawns it and
then *polls* `payload_for` (a short sleep loop) until the entry appears before the UI can
sign. It works and is deterministic in the test, but a sleep-until-registered loop is a
smell; a cleaner design would have the queue expose a synchronous "register then await"
split. Logged for a future agent-core ergonomics ask.

**2. The live dock isn't rewired to `LiveQueue` yet.** The real queue is *proven* (the
end-to-end test) and *available*, but the running dock still decides quorum through
STUDIO-3's `policy::quorum_satisfied` seam. Routing the live UI's sign flow through
`LiveQueue` (holding it in `RunState`, opening on gate-pause, observing resolution to
advance the gate) is real integration work I scoped as the next step rather than rush.
So "the real queue decides the gate" is true in test, and one wiring step from true in
the UI.

**3. The shipped capsules are unverified.** They carry placeholder `content_hash`es
(signing is CIT-AGENT-3e, upstream), so dispatching them sets
`CITRATE_ALLOW_UNVERIFIED_CAPSULES` — a loudly-logged dev opt-in. Honest, but it means
real *signed* dispatch waits on the packer.

**4. Chain writes are deferred.** Reads are unauthenticated and landed; anchoring needs a
funded signer + gas. The seam (`anchor_available()` gated on a `CITRATE_ANCHOR_KEY`) is
present and labelled, but no real anchor was written this sprint.

## Honest Assessment of Where We Are

**Strong:**
- All four live surfaces are *real* under core-live and proven by tests: real signatures
  through the real async queue, a real capsule executed through wasmtime, real chain
  reads against 40204, a real Doctor against a real chain.
- The architecture thesis is fully vindicated: studio is a viewport, the real core does
  the work, and the seams the earlier sprints built were the right ones.

**Needs work:**
- Live-dock rewiring to `LiveQueue`; chain *writes*; signed-capsule dispatch
  (CIT-AGENT-3e); the L0 agent loop (CIT-AGENT-3). These are integration + upstream, not
  unknowns.
