# Retrospective — STUDIO-8 (interactivity + e2e harness)

## The Numbers

| Metric | Value |
|---|---|
| e2e harness | `e2e_gate_sign_resume_audit_loop` — full operator loop, headless, both builds |
| Intents extracted | `apply_sign`, `apply_resume` (callbacks now delegate) |
| Transitions asserted | play → paused-at-gate → 1/2 → quorum → resumed → done → audit-verified |
| Builds | default 35 tests / core-live 39, both zero warnings |
| STUDIO-1 debt | closed (the flagged "no e2e harness" gap) |

## What Went Well

**1. The debt closed cleanly because the seams were already there.** STUDIO-1's retro
flagged "interactive behavior verified by reading the wiring, not by driving it." Eight
sprints later, closing that gap was a small change — because every prior sprint had kept
the logic testable (the `tick` state machine, the `policy`/`audit_verify` seams, the
`LiveQueue` bridge). The e2e test just had to *compose* them. Debt that's been kept small
is cheap to pay.

**2. Extracting the intents made the UI and the test share one path.** Pulling
`apply_sign`/`apply_resume` out of the callbacks means the e2e drives the *exact* code the
dock runs — not a re-implementation that could drift. The callbacks became one-line
delegators, which also made `main()` a little clearer. One behavior, one code path, two
callers (the UI and the test).

**3. It runs under both builds.** The same e2e passes default *and* `core-live`, and under
`core-live` the sign step drives the real async `ApprovalQueue`. So the harness doesn't
just test the modeled loop — it tests the *real* approval path end-to-end when the real
core is compiled in. That's the strongest version of the assertion.

## What Didn't Go Well

**1. No true mouse-event simulation.** Slint's `set_platform` is once-per-process, which
makes spinning up multiple full UI sessions in a test suite awkward, and there's no clean
public API to synthesize click events into a compiled component. So the harness drives the
*intents* the clicks invoke, plus the real `refresh→AppState` bridge — equivalent coverage
of the *behavior*, but it doesn't prove a literal pixel-at-(x,y) click lands on the Sign
button. That last mile (hit-testing) is unverified by automation; it's covered by the
headless snapshot review instead. Honest gap, not a hidden one.

**2. dry-run/solo still don't affect *real* dispatch.** The planset bundled these with the
e2e. The flags flow to state, but the canvas playback is a modeled timer — there's no real
`CapsuleDispatch` behind it yet, so "affect real dispatch" has nothing real to affect. I
declined to fake it. This is the same boundary as chain-writes: the tactile features are
gated on wiring the canvas to the runtime's dispatcher, which is the genuinely-large "live
run from the canvas" piece still ahead.

## Honest Assessment of Where We Are

**Strong:**
- The full operator loop is now covered by an automated, assertion-rich, both-builds e2e
  test. The longest-standing test debt in the project is closed.

**Needs work:**
- Literal input-event simulation (hit-testing) is still review-by-snapshot, not automated.
- dry-run/solo/reorder → *real* dispatch awaits the canvas→`CapsuleDispatch` wiring — the
  last big live-operation piece.

## The Partnership Dynamic This Sprint

Larry's standing instruction — finish, harden, don't fake, don't minimize the architecture
— made the dry-run/solo call easy: the honest move was to *not* implement "affects real
dispatch" against a modeled timer and to say so, rather than wire the flags to a fake
effect for a green checkmark. The sprint's real win, the e2e harness, was worth more than a
hollow one would have been. Paying a long-standing debt felt better than papering over a
new one.
