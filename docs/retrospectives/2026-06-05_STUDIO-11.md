# Retrospective — STUDIO-11 (visual e2e harness)

## The Numbers

| Metric | Value |
|---|---|
| Surfaces captured | 19 (every view, overlay, settings section, run state, scrubber tamper) |
| Outputs | browsable HTML gallery + 19 committed golden baselines |
| Regression gate | PIL mean-pixel-diff; validated it catches drift (5.74 > 2.0) |
| Modes | capture · update · check; `STUDIO_CORE_LIVE=1` for real-core states |
| Playwright | scoped honestly to web surfaces (scaffold in `tests/web-playwright/`) |

## What Went Well

**1. The honest answer was the better engineering.** "We need Playwright" met a hard fact:
Playwright drives browsers; this is a native Slint app with no DOM. Rather than build a
Playwright harness that can't attach to anything, the right tool was the software-renderer
snapshot harness — which I already had the pieces for (the `CITRATE_STUDIO_SHOT` headless
path + the env seeds). The constraint pointed straight at the correct design.

**2. The env-seed surface paid off hugely.** Every sprint that added a seed
(`CITRATE_STUDIO_SEED`, `OVERLAY`, `SECTION`, `TAMPER`, `SIGNEDIN`, `VIEW`, `WS`, …) was, in
hindsight, building the harness's API. STUDIO-11 just enumerated them. 19 distinct real app
states, captured in one script, because the app was already drivable from the outside.

**3. The gate is real, not theater.** I validated that `visual-diff` *catches* a regression
by swapping a baseline and confirming it flagged (mean 5.74 > the 2.0 threshold), then
restored. A regression gate you haven't seen fail is a gate you don't know works.

## What Didn't Go Well

**1. Golden images are platform-specific.** The software renderer's anti-aliasing differs
across OSes, so the macOS-rendered baselines would noise-fail on a Linux runner. I pinned the
CI gate to macOS and documented per-platform re-baselining — honest, but it means the visual
gate isn't trivially cross-platform. A perceptual-diff (SSIM) or per-platform baseline sets
would loosen this; the pixel-mean threshold is the simple version.

**2. It captures *rendering*, not *interaction sequences*.** Each tile is a state reached via
a seed, not a recorded click-path. The behavioral e2e (gate→sign→resume→audit) is covered by
STUDIO-8's harness; this one proves every surface *renders right* and *hasn't drifted*. Two
harnesses, two questions — which is correct, but worth stating so neither is mistaken for the
other.

**3. The Playwright scaffold can't run yet.** It's a template pointed at a web target that
doesn't exist. That's honest scaffolding (the right tool, documented, ready), but it's not a
running test — and I marked it as such rather than implying web coverage exists.

## Honest Assessment

**Strong:** every studio surface is now captured as an image, browsable in a gallery, and
gated against visual regression — exactly "confirm everything works in images," with the
right tool for a native app.

**Needs work:** cross-platform baselines (or perceptual diff); the web Playwright path is a
scaffold until a web surface exists.

## The Partnership Dynamic

Larry asked for "a really strong harness that runs Playwright." The honest move was to *not*
do exactly that — Playwright can't drive a native app — and instead build the equivalent-
strength native harness while explaining why, and scaffolding Playwright where it genuinely
applies. He'd told me, sprints ago: answer the hard questions, don't take shortcuts, don't
minimize the architecture for unimportant reasons. Building a Playwright harness that silently
couldn't work would have violated all three. The strong native harness honors the request's
*intent* — visual confidence in every surface — which is what he actually wanted.
