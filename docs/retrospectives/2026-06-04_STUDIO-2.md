# Retrospective — STUDIO-2 (authentication: OIDC + SIWE)

## The Numbers

| Metric | Value |
|---|---|
| Auth tests | 9 (PKCE RFC-7636 vector, authorize URL, signer_id, claims decode+validate, query parse, token-response parse, file-store roundtrip, loopback capture, token exchange via mock) — 17 total |
| New runtime deps | `ureq` (rustls), `tiny_http`, `keyring`, `getrandom` |
| Deps dropped vs the ADR | `jsonwebtoken` + JWKS (TLS-trusted ID token per OIDC §3.1.3.7) |
| Default build | zero warnings |
| `cargo audit` | 1 advisory (documented), 0 vulnerabilities in the default build |
| Cross-repo | `citrate-studio` OIDC client registered in `citrate-identity` |

## What Went Well

**1. The scaffold-first split paid off.** STUDIO-2 landed in two clean halves: a pure,
unit-tested core (PKCE, token model, store, claims) reviewed on its own, then the
network/keyring/UI on top. By the time the trust-bearing network code arrived, the crypto
and parsing underneath were already green — the review surface for the heavy half stayed
small.

**2. Choosing sync HTTP fit the app.** Slint is not async. `ureq` (blocking, rustls, no
openssl) + `tiny_http` for the loopback let the whole flow be a plain blocking function
run on a worker thread, with the result marshalled back via
`invoke_from_event_loop`. No tokio, no async bridging into the UI — far less rope than
`reqwest` would have handed me.

**3. The in-process mock tested the real flow logic.** Spinning a `tiny_http` `/token`
server inside a test and pointing `exchange_code` at it — plus firing a raw callback at
the loopback listener — exercises the actual capture + exchange + parse path without a
live IdP. That's the difference between "the types line up" and "the flow works."

**4. The dependency call shrank the trust surface.** Dropping JWKS/`jsonwebtoken` wasn't
laziness — it's the OIDC-sanctioned native code-flow path (§3.1.3.7: the ID token is
trusted via the TLS channel to `/token`). On a Tier-1 surface, removing a crypto
dependency you don't need is a security win, not a shortcut. Validating iss/aud/exp keeps
the defense-in-depth.

## What Didn't Go Well

**1. The live end-to-end is unverified here.** I cannot stand up a real
`citrate-identity` server in this environment, so the sign-in flow is tested against
in-process mocks, not a live IdP. The code path is complete and pointed at a real server
via `CITRATE_STUDIO_ISSUER`, but "works against the mock" is not "works against
auth.citrate.ai." **Action**: a federation e2e harness (identity + studio together) owns
that proof; flagged for STUDIO-5/integration so it isn't quietly assumed.

**2. The ADR over-specified the deps before the code existed.** It named
`reqwest`/`jsonwebtoken`; the implementation chose `ureq` and dropped JWKS. The ADR was
right on the *shape* (loopback PKCE, keyring, auth-keys ≠ signer-keys) but wrong on two
dep choices. **Lesson**: ADRs should commit to the architecture and the *constraints*
(sync-friendly, minimal trust surface), and leave specific crate picks to implementation
where the trade-offs are concrete — then amend the ADR, which I did in the sprint.

**3. The keyring touches the real OS keychain.** `session_from_store` reads the macOS
Keychain at startup; on a fresh machine that's a silent miss, but the first real *save*
can prompt. That's correct production behavior, but it means the store isn't unit-tested
against the real backend (tests use `FileTokenStore`). Acceptable — keyring is a thin,
well-trodden crate — but stated so the audit knows the keychain path is covered by the
crate's tests, not ours.

## Honest Assessment of Where We Are

**Strong:**
- A complete, parity-with-the-web-RPs native auth client: sign-in, logout, refresh,
  keyring storage, a session chip — off-thread, zero-warning, tested.
- A deliberately minimal Tier-1 trust surface (no JWKS crypto we don't need).

**Needs work:**
- No live-IdP proof in CI (mocks only) — a federation e2e concern.
- Auth establishes *who* (a wallet); it does not yet make that wallet a *signer*. The
  identity→role enrollment with real ed25519 keys is STUDIO-4, by design.

## The Partnership Dynamic This Sprint

Larry said "finish STUDIO-2 auth network/UI" and let me run to the gate. The judgment
call — dropping JWKS on a §3.1.3.7 reading — was mine, and the method made it safe to
make in the open: amend the ADR, record it in the sprint, justify it in the retro. The
recurring pattern across STUDIO-2/3 holds: the Agentile discipline of *writing down the
deviation* is what lets an agent make the honest engineering call instead of either
asking for every micro-decision or hiding the ones it makes.
