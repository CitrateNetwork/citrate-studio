# Retrospective — STUDIO-14 (signed installers)

## The Numbers

| Metric | Value |
|---|---|
| Bundle | `Citrate Studio.app`, 16 MB release, `ai.citrate.studio`, `AppIcon.icns` |
| Cert available | real `Developer ID Application: Larry Klosowski (DDHUG44QC7)` |
| Signing infra | `packaging/entitlements.plist` + `scripts/sign-macos.sh` (sign → verify → notarize-if-creds) |
| Gates | Developer-ID signing = interactive keychain auth; notarization = notary creds |

## What Went Well

**1. A real `.app` came out of `cargo bundle`.** Not a mock — a 16 MB release binary
(stripped, LTO) in a proper bundle with `Info.plist`, the `AppIcon.icns`, and the
`ai.citrate.studio` identity. The packaging metadata from STUDIO-9 paid off; one command
produced the artifact.

**2. The signing path is real, not theoretical.** A genuine Developer ID cert is in the
keychain, so `scripts/sign-macos.sh` does *real* Developer-ID signing (hardened runtime,
timestamp, entitlements), not ad-hoc. The same script runs locally and in CI; the entitlements
are minimal and correct (the shipped default build has no JIT — wasmtime is a dev-only build).

**3. The icon was fixed properly.** cargo-bundle's "No matching IconType" meant it couldn't
synthesize an `.icns` from arbitrary PNGs. The right fix was an Apple `.iconset` (the named
`icon_16x16@2x.png` … sizes) → `iconutil -c icns` → a real 200 KB `.icns` from the brand SVG.
One source (the SVG), the format macOS actually wants.

## What Didn't Go Well

**1. I couldn't execute the Developer-ID signing here.** `codesign` needs the keychain's
private key, and macOS protects it: a non-interactive process can't use it without prior
authorization, so `codesign` hung waiting for a UI prompt and was killed (exit 143). This is
not a bug to fix — it's the OS refusing to use a signing key headlessly. So the signing
*execution* is a step Larry runs in his interactive session (`scripts/sign-macos.sh`, click
*Always Allow* once); CI does it non-interactively by importing the cert into an *unlocked
ephemeral* keychain. The bundle and the script are done; the one keystroke is his.

**2. cargo-bundle's ad-hoc signature is subtly broken.** The `.app` cargo-bundle emits reports
"code has no resources but signature indicates they must be present" — its ad-hoc sign is
incomplete. `sign-macos.sh`'s `codesign --force --deep` re-sign fixes it, but it means the
unsigned bundle isn't itself shippable; the sign step is mandatory, not optional polish.

**3. Notarization is untested here.** No notary profile exists in this environment, so the
notarize → staple path is wired and documented but not exercised. It activates when Larry runs
`xcrun notarytool store-credentials`.

## Honest Assessment

**Strong:** a real signed-installer pipeline — real bundle, real cert, real signing script,
correct entitlements, CI integration — everything that can be done without Larry's keychair
keystroke and Apple notary creds.

**Needs work (both are his to unlock, not code):** run the interactive signing once; add a
notary profile to notarize.

## The Partnership Dynamic

This sprint drew a clean line between what an agent can finish and what only the human can
authorize. I can build the bundle, write the signing script, get the entitlements right, wire
the CI — but I *cannot*, and *should not be able to*, use Larry's private signing key without
his explicit keychain authorization. That's the system working as designed: the key is his,
the keystroke is his. The honest deliverable was to do everything up to that line, make the
final step one command, and say plainly that the last move is his to make.
