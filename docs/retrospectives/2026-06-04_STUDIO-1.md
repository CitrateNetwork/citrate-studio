# Retrospective — STUDIO-1 (Slint port of Citrate Studio)

## The Numbers

| Metric | Value |
|---|---|
| `.slint` files | 16 (10 components + theme/typography/icons/primitives/models/studio) |
| Slint lines | ~3,750 |
| Rust lines | ~1,355 (`main.rs` core + state machine, `data.rs` demo catalog) |
| Icons ported (single-Path, 24×24) | 45 + 7 capability glyphs |
| Surfaces realized | onboarding · Beginner chat · two-zone canvas/scrubber · dock · inspector · code drawer · health report · break-glass · settings/RBAC |
| Build warnings at close | 0 |
| Renderer | software (winit), headless snapshot path for review |

## What Went Well

**1. The kit-level decisions paid for themselves.** Putting colors, type, motion, and
the risk-tier system into a single `Theme` global (1:1 with `tokens.css`) meant every
component referenced tokens, never hex — exactly the web kit's `var(--*)` discipline.
When a panel looked wrong, the fix was one token, not a hunt. The `Palettes` global
(pure functions for tier/data-class/role colors) kept components declarative.

**2. `SelectableText` solved the headline requirement cleanly.** The "you can't
highlight text in our Slint apps" complaint had a one-component answer: a read-only
`TextInput` styled to look like a label. Built once, used everywhere content matters
(hashes, DIDs, outputs, code). It's the kind of fix that's invisible when present and
infuriating when absent.

**3. The headless snapshot loop, once built, was the productivity engine.** Render a
state, crop a panel at 2×, view it, fix, repeat. It turned "I think this matches" into
"here is the pixel." Every claim of fidelity in the close note is backed by an image I
actually looked at.

**4. The trust boundary held under porting pressure.** It would have been easy to let
a `.slint` file compute "approved." Instead quorum/SoD/hash-pin live in Rust and the
UI renders `approval-roster` + `quorum-met`. That discipline means wiring the real
`agent-core` later is a swap, not a rewrite — and the audit story stays honest.

## What Didn't Go Well

**1. I conflated "blank capture" with "blank UI" and bisected the wrong layer.**
Detailed in the journal (`docs/journals/2026-06-04T2100_the-blank-window.md`). I
swapped renderers three times chasing a snapshot-surface problem before realizing the
capture path, not the scene, was the first failure. **Action**: when a visual check
fails, prove the capture method on a known-good trivial scene *first*.

**2. I trusted a hand-rolled PNG sampler that ignored row filters.** It reported
"blank" on images that had content. I verified against my own broken instrument.
**Action**: verify against the real artifact (a real decoder / the Read tool), never a
bespoke parser, for go/no-go calls.

**3. Slint's layout defaults cost real time.** Elements default to 100%-of-parent; a
`Rectangle`-rooted component doesn't size to its content; a conditional `if` isn't a
stretchable layout slot; several intuitive property names are reserved
(`color`, `row`, `col`). None are hard once known, but I learned them by hitting them.
**Action**: the essay (`docs/essays/...porting-a-react-prototype-to-slint.md`) writes
these down so the next port doesn't re-pay the tuition.

**4. A few fidelity nuances are approximations, not exact.** The `⧗`/`☑` glyphs fall
back (not in Geist); output-card overlap with clips is close but not identical to the
CSS z-stack; the critical risk-badge dot overflows slightly. Logged here so the audit
doesn't read "1:1" as "identical to the sub-pixel."

## Honest Assessment of Where We Are

**Strong:**
- A complete, runnable, zero-warning native app that matches the prototype across
  every surface and state I could capture.
- A reusable UI kit (tokens, selectable text, icons, primitives) ready to extend to
  `gui-native`.
- The trust boundary is real, not aspirational.

**Needs work:**
- It is a faithful **shell over a modeled core.** No real `agent-core`, no auth, no
  persistence, no live chain/audit data, no new-user setup, no packaging. That is the
  whole of the roadmap planset (STUDIO-2+), not a footnote.
- Interactive behavior is verified by reading the wiring + smoke runs, not by driving
  clicks (the headless path renders state, it doesn't click). A real e2e harness is a
  STUDIO-3 item.

## The Partnership Dynamic This Sprint

Larry set the bar — "pixel perfect," "reactive," "highlightable text," "extend to all
native apps" — and otherwise gave latitude. That worked because the prototype was a
precise contract: when unsure, I rendered and compared rather than asked. The one
place I should have asked sooner was nothing about design and everything about
tooling — I burned time solo on the headless-capture problem that a single "the window
isn't presenting in this shell" framing would have shortcut.
