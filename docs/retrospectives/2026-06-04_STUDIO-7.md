# Retrospective — STUDIO-7 (hardening: button up every edge)

## The Numbers

| Metric | Value |
|---|---|
| `#[allow(dead_code)]` removed | 5 module-level (all) |
| Dead scaffold deleted | STUDIO-2 auth roster (`signer_id_from_pubkey`, `RosterEntry`, `enroll`, `Claims.sub`) |
| Test-only bridges wired into the UI | KYC badge, real `DoctorReport`, real capsule dispatch button |
| Unused-in-bin APIs wired | `authorized`, `CHAIN_ID`, `anchor_available` |
| `unwrap`/`expect` triaged | 54 → **7 non-test, all provably safe** |
| Builds | default 34 tests / core-live 38 tests, both zero studio warnings |

## What Went Well

**1. The "remove the allow and read the warnings" technique mapped the real dead code.**
Five `#[allow(dead_code)]` were masking the truth. Stripping them turned the compiler into
the auditor: it named exactly what was unused, per build. That's far more reliable than
grepping for "stub" — the compiler can't be fooled about what's actually called.

**2. The dead code told a story.** Most of it was STUDIO-2 auth scaffold that STUDIO-4's
`signing.rs` superseded — `signer_id_from_pubkey`, `RosterEntry`, `enroll`. Deleting it
wasn't loss; it was removing a draft the final design replaced. The codebase got smaller
and truer at once.

**3. "Wire it, don't allow it" was the right call on the bridges.** The STUDIO-6 dispatch
and doctor bridges were proven by tests but unused in the binary. The shortcut would've
been a blanket `allow`. The honest fix was to surface them: a real Doctor in the Health
Report (with a *computed* summary and LED, not hardcoded), and a "Run smoke capsule"
button that dispatches `hello` through wasmtime. The dead code became live features.

**4. The unwrap audit deflated a scary number.** "54 unwraps" sounds alarming; the triage
showed 47 were test assertions and the 7 real ones are each provably safe — a guarded env
var, a `last()` right after `push`, single-thread mutex locks, and entropy/runtime
construction. Counting honestly beat counting loosely.

## What Didn't Go Well

**1. Rapid rebuilds corrupted the incremental cache.** A burst of `touch` + `cargo build`
+ `cargo test` produced a real linker failure — `Undefined symbols … _anon.*.llvm.*` — that
looked like a code error but was stale incremental artifacts. `rm -rf target/debug/incremental`
fixed it. **Lesson**: when the linker complains about LLVM anon symbols after a flurry of
partial builds, suspect the cache before the code; and don't `touch` source files to force
rebuilds — it's what poisoned the cache.

**2. `cfg_attr` allows are correct but easy to over-trust.** The default-build signing path
(`sign_for`, `data::doctor`) is genuinely unused in the `core-live` binary, so
`#[cfg_attr(feature = "core-live", allow(dead_code))]` is accurate — *today*. If a future
sprint makes the core-live UI also call `sign_for`, the allow silently becomes a lie. These
annotations carry an implicit "as of now"; they want re-checking whenever the cfg topology
shifts. Noted so a future reader doesn't trust them blindly.

**3. Some demo content is still hardcoded.** The Boeing scenario, the RBAC directory, the
account name/email are prototype content, not real-tenant data. I fixed the one true
*inconsistency* (the Account signer-id now matches the real roster), but "every line shows
real data" isn't achievable without a real tenant — and conflating demo content with tech
debt would be the wrong kind of thoroughness.

## Honest Assessment of Where We Are

**Strong:**
- The codebase is dead-code-clean under both builds; every former `allow` is either gone or
  a precise, justified `cfg_attr`. No user-triggerable panic in the live path.
- The STUDIO-6 capabilities are no longer test-only — they're surfaced in the UI.

**Needs work:**
- The `cfg_attr` allows are correct-as-of-now and want re-checking when the cfg topology
  changes.
- The genuinely-upstream seams (chain writes, signed-capsule packing, the L0 loop) remain —
  labelled, gated, and outside studio's code to write.

## The Partnership Dynamic This Sprint

Larry's instruction was the strongest yet: "leave no line of code unturned … buttoned up to
the max … no tech debt … don't minimize the architecture for reasons that aren't important."
That last clause did real work. It's why I *kept* `signature_count` (a clean accessor) with a
precise allow instead of deleting it to dodge a lint, and why I *wired* the dispatch/doctor
bridges instead of allowing them dead. "Hardening" can degrade into "delete anything the
linter flags"; his framing kept it as "make every line either used-and-correct or
honestly-annotated." That's the version of finished worth shipping.
