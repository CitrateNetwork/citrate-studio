# Retrospective — STUDIO-5 (persistent from-scratch setup)

| Metric | Value |

## What Went Well

**1. Onboarding now leaves the system configured.** Each of the six steps performs a
real action and writes a `citrate-studio.toml`: workspace/tenant, the chosen runtime,
the installed-capsule count, the oversight default, the first prompt, and the
`onboarding_complete` flag. First launch routes to onboarding; once the flag is set, the
next launch goes straight to Studio. The difference between a wizard and theatre is
whether closing it changed anything — this one does.

**2. Discovery is a real probe, surfaced honestly.** The runtime step doesn't claim "I
found a few on your network" unconditionally. It actually probes Ollama (:11434) and
llama.cpp (:8080) over HTTP with a short timeout and *says what it found* — and when
nothing answers (the common case on a fresh machine), it says so and falls back to the
embedded Gemma. An honest "nothing answered" beats a scripted "I found things."

**3. Capsule install is fail-closed with real crypto.** `install_capsules` verifies each
capsule's ed25519 publisher signature and installs only the ones that check out; the
demo set includes a `rogue.exfiltrate` capsule with a bad signature that is *rejected*,
and a test pins that 5 install and 1 is refused. The planset's "anything unsigned stays
locked" is enforced, not narrated.

**4. The debts got paid, not deferred again.** `new_state_with` now injects both the
roster and the config, so no unit test reads `$HOME`; the production `new_state` does the
disk reads. Keyring is the prominent default enrollment surface. Paying a prior sprint's
debt the very next sprint is how debt stays small.

**5. Extracting `onboard_apply` made the flow testable.** Pulling the per-step config
mutation out of the UI-coupled `handle_onboard` into a pure function let me drive all six
steps in a unit test and assert the built config — no window, no `$HOME`, no network.

## What Didn't Go Well

**1. The full UI-driven conversation isn't headless-testable.** I can't drive the
chat-based onboarding through a real `StudioWindow` in a unit test, so the e2e coverage
is `onboard_apply` (the logic) + the config module (the persistence) + a manual
screenshot, not a single click-through-the-flow test. That's a reasonable decomposition,
but it means "click every step in the real UI and confirm the file" is still a manual
check. A future input-injection harness would close this.

**2. Flat TOML by hand has a sharp edge.** I wrote a minimal TOML reader/writer to avoid
pulling `serde`-derive + the `toml` crate. It works and is tested — but the first cut had
a real bug: `trim_matches('"')` stripped *escaped* inner quotes too, mangling a prompt
containing `"`. Fixed by stripping exactly one delimiter quote per side. Hand-rolled
formats save a dependency and cost you the parser's edge cases; the test caught this one,
but it's a reminder that "just a flat config" still has corners.

**3. Some steps configure a stand-in, not the final thing.** The roster step largely
*confirms* the STUDIO-4-seeded roster rather than re-enrolling per choice; the capsule
sources are a demo set, not a real `.cps` registry feed; and the first prompt is captured
but not yet *run* by a real agent. Those are correct deferrals (the registry and the
agent loop are STUDIO-6), but it means setup configures a real, persisted *intent* whose
*execution* arrives later.

## Honest Assessment of Where We Are

**Strong:**
- A clean machine now goes onboarding → a persisted, real configuration → Studio, and
  stays in Studio thereafter. Discovery and capsule install are real and fail-closed.
- Two prior debts paid; tests are `$HOME`- and network-free.

**Needs work:**
- Setup configures intent that STUDIO-6 turns into execution (live runtime binding, real
  capsule dispatch, the first prompt's agent run).
- The conversational flow's only true e2e is manual.

essays I owed — and he was right; the trail had gaps. Backfilling them first meant

"the agent decided something" into "the agent decided something, and here is why, where
you can check it."
